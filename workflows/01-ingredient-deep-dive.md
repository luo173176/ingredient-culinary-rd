# 工作流 01 · 食材深度研究

## 目的

把一种食材研究到“能判断、能挑选、能替代、能下锅”的程度，而不是罗列百科词条。

## 触发

- “XX 是什么食材/怎么样/怎么挑/怎么保存/怎么吃”
- “帮我系统研究一下 XX”
- “XX 的产地、品种、时令、风味”

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 食材名 | 是 | 允许别名、俗名、地方名 |
| 用途 | 否 | 家常/餐厅/研发/教学 |
| 地域 | 否 | 用户所在地，影响时令与替代 |
| 限制 | 否 | 过敏、宗教、忌口、设备 |

## 检索计划

1. 名称归一化：查 `config/ingredient_lexicon.json`，得到 canonical + aliases。
2. 按 canonical 检索四书；再按别名补检一次。
3. 必查维度：产地/品种、时令、品质、香气、味道、口感、烹饪、搭配、保存、安全。
4. 本草属性只在命中《中药学》时写；没有就明确写不适用/无依据。
5. 至少跨 2 本书；若只有 1 本有内容，说明其余书未覆盖。

## 步骤

### 1. 建证据表

先列 E1…En，每条含书名、页、章节、原文/忠实摘要、conf。

### 2. 写“一句话结论”

不超过 60 字，只写有证据支撑的判断。例：
> 花椒在本知识库中表现为“香气突出、麻味明确、温中止痛”的调味兼本草食材；产地与品种差异主要依据《中药学》与《中国地道食材图录大全》。

### 3. 按 17 个知识域填充

基础信息 → 别名 → 分类 → 产地品种 → 季节 → 外观品质 → 香气 → 味觉 → 口感 → 本草属性 → 传统应用 → 烹饪 → 搭配 → 替代 → 加工保存 → 安全 → 来源。

无依据的字段写 `null` + 原因，不删字段。

### 4. 冲突处理

不同书对同一食材的产地、性味、用法不一致时：

```markdown
**来源冲突**
- 《A》认为：……［E1］
- 《B》认为：……［E2］
- 处理：并列保留；现有四书不足以判定哪一种更具普遍性。
```

### 5. 给出“怎么用”的三条建议

- 最适合的做法（有证据）
- 不建议的做法（有证据/安全）
- 可替代方案（有证据或标为假设）

## 输出模板

```markdown
# {食材} 深度研究

## 一句话结论
...

## 证据表
| ID | 来源 | 页/章 | 原文或忠实摘要 | 类型 | 可信度 |
|---|---|---|---|---|---|

## 1. 基础信息
- 中文名 / 别名 / 英文名 / 学名（有则写）
- 分类与烹饪角色

## 2. 产地与品种
## 3. 季节与上市期
## 4. 外观与品质鉴别
## 5. 香气
## 6. 味觉
## 7. 口感与质地
## 8. 传统本草属性（仅适用时）
> 以下为传统中医药理论，不是现代医学疗效证据。
## 9. 传统应用与理论依据
## 10. 烹饪方式
## 11. 风味搭配
## 12. 替代方案
## 13. 加工与保存
## 14. 安全与禁忌
## 15. 知识缺口
## 16. 来源
```

## 质量检查

- [ ] 每个维度要么有 E 编号，要么写“无依据”。
- [ ] 没有把别名当独立食材重复计算。
- [ ] 没有把传统功效写成治疗结论。
- [ ] 产地/时令没有跨书硬合并。
- [ ] 至少 3 条可执行建议。

## 安全边界

涉及药食同源、孕妇、儿童、慢病用药时，加一段“先咨询医生/药师”；不给个体化剂量。

## 示例检索

```bash
python scripts/search.py "花椒 产地 品种 性味" --top 8
python scripts/search.py "川椒 蜀椒" --top 6
python scripts/search.py --herb 花椒
```
