# 风味搭配证据政策

## 1. 先分清四件事

1. **书中直接条目**：某食材条目明确列出一个搭配词。
2. **书中组合条目**：Flavor Affinities 以加号列出多个成员。
3. **索引推导**：把组合拆成两两关系，或从同一条目跨行重建。
4. **AI 创新**：为了新菜提出的、书中没有的组合。

这四类不能混写。输出时必须使用 `[原文]`、`[跨来源推理]`、`[创新假设]` 或 `[知识库缺口]`。

## 2. 证据等级与表述

| 等级 | 可以说 | 不可以说 |
|---|---|---|
| `explicit_pairing_listing` | “书中 BASIL 条目列出 TOMATOES” | “所有罗勒番茄菜都经过验证” |
| `explicit_affinity_combination` | “书中的 affinity 把 A、B、C 列为一组” | “A+B 是最佳二元搭配” |
| `derived_from_affinity_combination` | “由书中组合拆出的 A–B 关系” | “书中逐字写了 A+B” |
| `ai_hypothesis` | “AI 提出、待验证” | “书中推荐/科学证明” |

## 3. 页码与引文

- 必须有 `source_id=FB-PAGE-2008`。
- 同时有 `printed_page` 与 `pdf_page` 时写两者。
- 条目跨页时写清主条目页与续页。
- 短引不超过必要长度；不要把三栏 OCR 乱序整段当引文。
- 关键判断回看 `--page`，不要只看单行 JSON。

示例：

```text
[原文] 《The Flavor Bible》p.58（PDF 73），BASIL 条目直接列出 GARLIC。
[原文] 《The Flavor Bible》p.59（PDF 74），BASIL 条目续页继续列出搭配词。
```

## 4. 搭配强度

当前可用的强度信息只有：

- 是否直接列出；
- 是否来自 affinity 组合；
- `strong_marker` 的版面候选；
- 条目页上下文。

没有统一的 0–1 科学强度评分。不得把出现次数或排名分当“相容概率”。

## 5. 与食品化学组合

食品化学可用于解释：

- 香气挥发与温度；
- 脂质对香气物质的承载；
- 酸、糖、盐对感知的影响；
- 加热产生的香气变化。

但这些解释不自动证明某个组合好吃。正确写法：

```text
[原文] 书中有 A 与 B 的搭配记录。
[跨来源推理] A 的香气方向与 B 的脂质/酸度在机制上可能互补。
[创新假设] 在特定比例和温度下，该组合可能形成更完整的层次。
[验证] 需设置对照和盲评，当前未做实验。
```

## 6. 安全边界

- 风味搭配不是营养协同或药理协同。
- 不把“能搭”解释为“适合所有人”。
- 过敏原、药物相互作用、妊娠、儿童和疾病人群必须单独提示。
- 书中没有覆盖的安全限量写：

> 当前十书知识库暂无充分依据。

## 7. 质量检查

- [ ] 名称不是 OCR 噪声或菜名。
- [ ] 证据等级与表述一致。
- [ ] 直接条目和组合推导没有混写。
- [ ] 页码真实存在。
- [ ] 没有把 AI 新想法写成书中原文。
- [ ] 没有声称未做的感官实验已经成功。
