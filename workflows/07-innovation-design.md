# 工作流 07 · 创新菜品设计

## 目的

做出“有新意但讲得通”的菜品：创新点可解释、可复现、可验证，而不是把不相干的食材堆在一起。

## 触发

- “做一个没人做过的组合”
- “把 A 菜系和 B 菜系融合”
- “用 XX 做一道创意菜”
- “给我三个创新方向”

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 起点 | 是 | 食材、风味、技法、文化母题、记忆点 |
| 约束 | 否 | 预算、设备、时间、忌口 |
| 目标 | 否 | 高级餐饮/家常/快闪/比赛 |

## 创新矩阵（至少选 2 轴）

| 轴 | 问题 | 例子 |
|---|---|---|
| 食材 | 能否换品种/部位/成熟度？ | 同一食材的不同质地 |
| 风味 | 能否换酸/脂/香气方向？ | 发酵酸替柠檬酸 |
| 质地 | 能否制造对比？ | 脆/滑/粉/弹 |
| 温度 | 能否冷热对比？ | 热菜冷酱 |
| 技法 | 能否换传热方式？ | 蒸→烤，炸→风干 |
| 文化 | 能否迁移饮食逻辑？ | 中式腌制 × 西式乳化 |
| 呈现 | 能否换形态？ | 卷/塔/汤/冰 |

## 步骤

1. 写“创新命题”一句话：`把 A 的 X 逻辑，用到 B 的 Y 食材上`。
2. 给 3 个方向，每个方向写：核心创意、风味逻辑、最大风险、验证方法。
3. 选 1 个方向做完整菜谱（走工作流 05）。
4. 标出哪些是 `[原文]`、`[跨来源推理]`、`[创新假设]`。
5. 设计一次最小验证：2 个变体 + 1 个对照。

## 质量检查

- [ ] 创新点能用一句话说清。
- [ ] 不是“食材堆砌”。
- [ ] 每个方向都有风险与验证。
- [ ] 没有把假设写成已成功。
- [ ] 保留至少一个“熟悉锚点”，避免完全不可吃。

## 安全边界

不为了“猎奇”使用有毒动植物、未熟豆类、野生菌、河豚等高风险原料。

## Phase 2 创新增强

### 创新证据三层

| 层 | 来源 | 输出要求 |
|---|---|---|
| 书中直接支持 | Flavor Bible 条目/affinity，或食材/烹饪书 | 书名、卷册、页 |
| 跨来源推理 | Food Chemistry 机制 + 食材结构 + 搭配条目 | 推理链、条件 |
| AI 创新假设 | 书中没有的组合或工艺 | 假设、变量、对照、指标 |

### 创新矩阵新增轴

- 化学机制：褐变、糊化、凝胶、乳化、氧化。
- 食材结构：纤维、蛋白、淀粉、脂质、水分。
- 加工方式：干制、腌制、发酵、低温/高温、传热。
- 搭配证据：直接搭配、组合推导、完全新组合。

### 检索示例

```bash
python scripts/search.py --pairing BASIL --top 30
python scripts/search.py "aroma compounds" --source FC-BELITZ-2009
python scripts/search.py "果实 成熟 香气" --source MCG-V2-2013
python scripts/search.py "乳化 酱汁" --source MCG-V1-2013
python scripts/search.py --chemistry "Maillard" --top 8
```

### 最小验证

- 至少 1 个对照 + 2 个变体；
- 固定原料品种、成熟度、切割尺寸和环境温度；
- 记录配方、设备、时间、重量；
- 盲评香气、甜酸、咸度、质地、苦涩、整体喜好；
- 没做实验时不得写“成功”“最佳”“消费者喜欢”。
