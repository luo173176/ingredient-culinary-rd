# 工作流 05 · 菜谱研发

## 目的

从“想做什么”到“能照着做、知道为什么、知道怎么改”的完整菜谱，而不是食材清单 + 步骤。

## 触发

- “给我设计一道 XX”
- “用 XX 做一道菜”
- “研发一个 XX 风味的菜”
- “做一份 2 人份的 XX”

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 菜品/目标 | 是 | 可以是风格、食材、场景 |
| 人数 | 否 | 默认 2 人 |
| 设备 | 否 | 灶、烤箱、空气炸锅、温度计 |
| 限制 | 否 | 过敏、忌口、时间、预算、厨艺 |
| 风格 | 否 | 家常、餐厅、fusion、传统 |

## 研发流程

### 1. 定位

写清：场景、风格、目标感官、难度、总时长。

### 2. 食材结构

按角色拆分：

- 主料：决定菜品身份
- 辅料：提供体积、水分、质地
- 香气：葱姜蒜、香料、香草
- 调味：盐、酸、鲜、甜、辣
- 脂：承载香气、传热、口感
- 质地/点缀：脆、滑、籽、叶

### 3. 风味设计

先定“主味 + 支撑味 + 尾味”，再选调料：

```text
主味：咸鲜（盐 + 氨基酸）
支撑：酸（柠檬/醋）+ 脂（黄油/油）
尾味：香料的苦香/辛香
```

### 4. 工艺设计

每一步写：动作、温度、时间、判断标准。优先选择可控的传热方式。

### 5. 配比

给出百分比或克数；盐建议以总重量的百分比记录（有依据时），并给可调范围。

### 6. 预演风险

- 出水
- 过熟/夹生
- 乳化失败
- 香料发苦
- 酸味过尖
- 过敏原

### 7. 迭代

标注 `validation_status`：`designed_only`（仅设计）或 `not_tested`。没有真实试做，绝不写“已验证/很好吃”。

## 质量检查

- [ ] 每步有可观察的判断标准（颜色、声音、质地、温度）。
- [ ] 所有用量有单位；盐、糖、酸有范围。
- [ ] 至少 3 个可调参数。
- [ ] 至少 2 条风险及补救。
- [ ] 没有把未试做的菜写成“已验证”。
- [ ] 过敏原与特殊人群提示完整。

## 安全边界

- 不设计生食淡水水产、生腌、未灭菌乳制品等高风险做法，除非明确标注风险并给替代。
- 不写“低温慢煮”却没有温度/时间控制。
- 不把药材当调料大量使用。

## Phase 2 研发增强

### 书籍依据的角色

- **Food Chemistry**：给机制和条件，不给“最佳家用温度”。
- **《食物与厨艺》**：解释食材结构、受热、酱料、乳蛋肉鱼与烹饪方法，必须写清卷册。
- **《The Flavor Bible》**：给搭配候选；区分直接条目、组合推导和 AI 假设。
- **《烹饪原料学》**：分类、品质、保藏、加工，2003 年版不是现行标准。
- **第一阶段四书**：产地、时令、感官、盐脂酸热和本草边界。

### 设计参数与书籍证据分开

表中至少分开三列：

| 设计项 | 书籍依据 | AI 设计参数/假设 |
|---|---|---|
| 盐度 | 书中是否给百分比/原则 | 本菜试验值 |
| 温度 | 书中机制或范围 | 设备设定值 |
| 时间 | 书中原则 | 按厚度/设备调整 |
| 搭配 | 直接条目/推导 | 新组合假设 |
